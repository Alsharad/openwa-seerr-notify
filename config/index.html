Point Seerr at this plugin

The Instances tab of this window holds the webhook URL and the secret, live — it creates them, shows them and copies them. This page is only what to do with them, so it never disagrees with it.

1 · On the Instances tab

Create an instance if you have none — an id is all it needs. Copy its webhook URL, and the secret it shows when you create it or regenerate one.

Leave Session scope blank: notifications go out from your connected WhatsApp session. Set it only if you run more than one and want a specific one.

2 · In Seerr → Settings → Notifications → Webhook

  • Enable Agent — on.
  • Webhook URL — the URL you copied.
  • Authorization Header — the secret. Leave the custom-header rows empty.
  • JSON Payload — leave it at Seerr’s default; press Reset to Default if you have edited it.
  • Tick the notification types you want. Who gets what decides who receives each one.

3 · Checking it works

Seerr’s Test Notification button works once. Its payload is identical every press, and OpenWA answers a repeat of an identical delivery with 200 duplicate without passing it on — the same rule that stops a retry from messaging people twice.

Use the health check on this plugin’s row instead: it reports the Seerr version and which WhatsApp session notifications will go out from. A real request in Seerr is the other honest test.
